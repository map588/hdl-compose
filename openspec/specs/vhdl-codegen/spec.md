## ADDED Requirements

### Requirement: Generate entity declaration from top-level ports
The codegen SHALL emit a VHDL entity declaration using `Schematic.top_name`, `top_generics`, and `top_ports`.

#### Scenario: Entity with ports and generics
- **WHEN** a schematic has top_name `"top_level"`, one generic `CLK_FREQ : integer := 100000000`, and ports `clk : in std_logic` and `led : out std_logic_vector(7 downto 0)`
- **THEN** the output SHALL contain a valid `entity top_level is` declaration with the generic and port clauses

### Requirement: Generate signal declarations for internal nets
For each net driven by an instance output that connects to at least one other port, the codegen SHALL emit a `signal` declaration. The signal name SHALL be the user alias if set, otherwise `<driver_instance>_<driver_port>`.

#### Scenario: Signal with alias
- **WHEN** net driven by `("u_pll", "clk_out")` has alias `"sys_clk"` and type `std_logic`
- **THEN** output SHALL contain `signal sys_clk : std_logic;`

#### Scenario: Signal without alias
- **WHEN** net driven by `("u_adc", "data_out")` has no alias and type `std_logic_vector(7 downto 0)`
- **THEN** output SHALL contain `signal u_adc_data_out : std_logic_vector(7 downto 0);`

### Requirement: Generate component declarations
For each unique module referenced by instances, the codegen SHALL emit a `component` declaration matching the module's generics and ports.

#### Scenario: One component per unique module
- **WHEN** three instances all reference module `fifo_sync`
- **THEN** output SHALL contain exactly one `component fifo_sync is` declaration

### Requirement: Generate instance statements with port and generic maps
For each instance, the codegen SHALL emit an instance statement with `generic map` (if generics exist) and `port map`.

#### Scenario: Instance with generic map and port map
- **WHEN** instance `u_fifo` of module `fifo_sync` has `DEPTH => 1024` and `clk => clk_sys`
- **THEN** output SHALL contain `u_fifo : fifo_sync generic map ( DEPTH => 1024 ) port map ( clk => clk_sys, ... );`

#### Scenario: Unconnected port emits open
- **WHEN** instance port `full` has no mapping (None)
- **THEN** the port map entry SHALL read `full => open`

#### Scenario: Instance port connected to internal net uses signal name
- **WHEN** instance port `din` is mapped to `NetRef::InstancePort("u_adc", "data_out")` with no alias
- **THEN** the port map entry SHALL read `din => u_adc_data_out`

### Requirement: Instances ordered alphabetically
Instance statements SHALL appear in alphabetical order by instance name.

#### Scenario: Stable ordering
- **WHEN** instances `u_fifo`, `u_adc`, `u_dsp` exist
- **THEN** they SHALL appear in order: `u_adc`, `u_dsp`, `u_fifo`

### Requirement: Architecture named structural
The architecture SHALL be named `structural`.

#### Scenario: Architecture declaration
- **WHEN** codegen runs for entity `top_level`
- **THEN** output SHALL contain `architecture structural of top_level is`

### Requirement: Header comment
The output SHALL begin with `-- Generated by hdl-compose. Edit the source .hdlc project file, not this file.`

#### Scenario: Header present
- **WHEN** codegen produces output
- **THEN** the first line SHALL be the header comment

### Requirement: Codegen refuses on validation errors
Codegen SHALL NOT produce output if the schematic has validation errors (warnings are acceptable).

#### Scenario: Validation error blocks codegen
- **WHEN** a schematic has a direction mismatch error
- **THEN** codegen SHALL return an error instead of producing output
